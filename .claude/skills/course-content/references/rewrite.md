# Rewrite mode

Rewrites pages that already exist into the `lesson.md` shape, keeping every topic, caveat and diagram. Input: a module or lesson (resolved with `resolve.py`), a file path, a forwarddeployedprep.com URL or pasted content, then `review` (default) or `edit`.

- **review**: return the rewritten page in chat. Change no file, publish nothing. Show each diagram's place with `[Existing diagram remains unchanged here]`; never write that placeholder into a file.
- **edit**: change only the authorised prose in the course README. The site's copy under `content/learn/` is generated by its importer from these READMEs; never edit it.

## 1. Inventory before writing

List every substantive topic on the original page: facts, distinctions, dependencies, conditions, limits, trade-offs, failure diagnosis, edge cases, safeguards. The rewrite may reorder sections and rename non-contract headings, but every item on the list must still be covered. Check the list again at the end.

## 2. Protected blocks (byte for byte)

- ` ```mermaid ` fences and the `<!-- animated: diagrams/<name>.anim.html -->` line after one.
- `<!-- lab: interactive/<name>.html -->` lines, and every file under `diagrams/` and `interactive/`.
- Image and SVG references (`![...](diagrams/...)`) with their alt text.
- Labels and order of all of the above. A diagram may move with the text it illustrates, but existing diagrams keep their relative order.

You may **add** Mermaid diagrams where `lesson.md` calls for a figure the page lacks (a shared skeleton, a check order, a decision flow), and add `*Figure N: …*` captions under old and new diagrams alike.

If a diagram looks wrong or contradicts the explanation, leave it and flag it. Do not bend the prose to match a wrong diagram. Run `scripts/protect.py --rewrite <file>` after an edit; it fails when a protected block from `git show HEAD:<file>` was changed, removed or reordered (added Mermaid blocks pass).

## 3. Contracts to keep (rewrite inside them)

- The italic header line with its notebook list.
- Each `## <concept>` heading from `concepts:`, word for word.
- `## Key Takeaways` and `## Check yourself` in their `contracts.md` shape, answers drawn only from the page. When Check yourself questions change, update that module's entry in `docs/fde-site-mistakes.yaml` if it quotes them.
- The previous/next footer.

## 4. Apply the theory-only rule

Follow `voice.md` → Theory only. In practice:

- An implementation-heavy section that teaches an important idea becomes theory about that idea, using `lesson.md` → Code becomes evidence; it is not dropped.
- `### Step N` headings become descriptive section headings or a numbered list.
- Remove existing code blocks, `### Practice notebook` sections and body notebook links. List each removal in the report so the user can check that the notebook covers it.
- A notebook-dependent exercise becomes a conceptual question.

## 5. Report

After the content (review) or the checks (edit), add a short note only when there is something to flag: factual uncertainties, coverage concerns, diagram inconsistencies, removed code blocks and the notebook that covers each.
